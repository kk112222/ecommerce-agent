# 12 · RAG 评测四层叙事

> 外部评审给了方法论，我落地成一套能跑、能复现、数字能讲出口的 RAG 评测。
> 这一章是**面试速记**：RAG 系统怎么证明自己不是"看起来能答"。
> 配套代码：`scripts/rag_eval.py`（检索 A/B）+ `scripts/rag_quality_eval.py`（生成端扰动 + judge）。

---

## 本章目标

读完这一章，你会明白：

1. RAG 一个回答要过**三段**：切分 → 检索 → 生成，评测为什么必须分层拆
2. 真值（Golden）怎么造才有**判别力**——虚构条款 vs 常识条款
3. 检索层四路 A/B 的**真实数字**和怎么讲（向量最弱、混合救回、精排兜底）
4. 生成层怎么测"模型老不老实"（扰动测试 + judge 忠实度）
5. 这套评测的**边界**——面试主动自曝反而加分

---

## 零、先记住一句话（全文钩子）

> **切分决定召回上限，检索决定能不能够到上限，生成决定够到之后老不老实。**

面试被问"你的 RAG 怎么保证效果"，就用这句话开场，然后按下面三层往下拆。
任何一个环节坏了，用户看到的都是同一句"答错了"，所以不拆层评测，你根本不知道 blame 谁。

---

## 一、评测地基：真值（Golden）怎么造

评测 RAG 先要有"标准答案"，也就是**一条文档里逐字存在的片段**。
这里藏着一个关键设计：

**不能用模型/检索器本来就猜得到的常识条款当真值。**
比如"退货要运费"这种常识，BM25、向量、甚至模型预训练全都命中 → 评测全部顶格满分，看起来很好，其实**没区分度**，证明不了任何东西。

我的做法：自建**虚构条款**，逐字写进知识库文档，比如：

- 运费险赔 8~12 元、满 99 元包邮、积分有效期 24 个月
- 限购 1 件、冷静期 15 天、重开发票最多 3 次 …

这些内容预训练**背不到**，只有真读过检索资料才答得上来 → 测的才是检索和跟随，不是模型记忆。

顺带两个工程点：
- 知识库扩到 **8 个文件、5 种格式**（md / html / txt / docx / pdf），一份 golden 同时给多格式解析当了回归测试。
- 共 **51 条 golden**，每条 = `(问题, 真值片段, 来源)`，真值片段唯一锚定一个块。

---

## 二、第 1 层：切分 —— 决定召回上限（面试冷门加分点）

这层不是直接测出来的，是**踩坑踩出来的**，反而最好讲：

**现象**：最早按 300 字段落切块，3 个短 md 只切成 7 个"大杂烩块"（一段里塞好几条问答/条款）。
评测结果：Recall@5 全部 100%、MRR 顶格 → 看着满分，其实是被切分"喂到嘴边"了，
**召回上限被粗块焊死，评测梯度被压没**。

**改法**（`build_kb.py` 结构化切块）：
- `##` 标题**强制开新块**（标题不腰斩段落）
- CHUNK_SIZE=200、OVERLAP=40（跨块上下文连续性，避免语义断在半截）

**结果**：7 块 → **32 块**，评测的梯度立刻出来了（见下一层的表）。
同时这是**正反两面互相印证**的完整证据链：粗块顶格 → 说明评测没区分度；细块出梯度 → 说明"切分决定召回上限"是真命题。

> 面试话术：不是块越小越好——太小丢上下文、embedding 语义变弱。
> 取舍是"粒度 vs 语义完整"，用标题边界 + 重叠来缓解，目标让每块尽量**单一事实**，方便按句定位。

---

## 三、第 2 层：检索 —— 四路 A/B 量化

**指标先记牢一句话版**：

| 指标 | 含义 | 关注什么 |
|---|---|---|
| Recall@5 | 真块在不在前 5 里 | 有没有把对的捞回来（上限） |
| Hit@1 | 第 1 条是不是真块 | 用户最常看第一条 |
| MRR | 命中的排名位次 | 对"首条不对但靠前"也公正 |

**四条策略 A/B**：BM25 / 向量 / 混合 RRF / 混合 + rerank（生产路径）。

**真实数字**（51 题，细切 32 块后，2026-09-05）：

| | BM25 | 向量 | 混合 RRF | 混合+精排 |
|---|---|---|---|---|
| Recall@5 | 96% | 63% | 100% | 100% |
| Hit@1 | 73% | 51% | 82% | **90%** |
| MRR | .819 | .565 | .894 | **.942** |

**怎么读（这就是面试要讲的三个结论）**：

1. **向量单跑最弱**（Hit@1 只有 51%）—— 条款/数值这类"精确关键词"问题，BM25 反而强。**单路各有盲区**，这是做混合的动机，不是玄学。
2. **混合 RRF 把 Recall 拉回 100%** —— RRF 不比较分数绝对值、只比排名位次，BM25 和向量**谁对都救得回来**，1+1>2。
3. **精排把 Hit@1 从 82 → 90** —— CrossEncoder 对 top-10 逐对语义重排。结论：**精排增益通常大于盲目加召回**，生产路径 51/51 全对、8 个来源各自全对。

复跑方式：`scripts/rag_eval.py`，**要停后端**（qdrant 本地模式单进程锁），约 90s。
改任何检索/切分代码，前后各跑一次，用这张表说话，而不是"我调了下感觉变准了"。

## 四、第 3 层：生成 —— 模型"老不老实"（最像审计的一层）

**动机**：检索顶格 ≠ 答案对。模型可能**绕过检索**，靠预训练/常识直接答（bypass）；
也可能资料里没有，也**硬编**一条。这两件事第 2 层测不出来，得看回答本身。

**判别前提还是"虚构条款"**：既然条款模型背不到，那——
- 我把资料里的值**改掉**，它还答旧值 → 它在 bypass，根本没看资料；
- 我把资料**清空**，它还能答出旧条款 → 它在编（幻觉）。

### 4.1 扰动测试

6 条条目，每条把某条款数值在"检索资料"里改掉（限购 1→5 件、包邮 99→129、积分 24→6 个月、冷静期 15→30 天…）：

- **V1 换值**：资料给了新值，问原问题 → 回答跟新值。**6/6 通过**（有在跟源，没背旧值）
- **V2 清空**：资料为空，问原问题 → 答不出旧条款（说"知识库暂无此信息"）。**6/6 通过**（没编）

**失败含义**：V1 低 → 模型靠记忆答题（真 bypass）；V2 低 → 没资料也敢编，系统提示词没约束住。

### 4.2 judge 忠实度（独立裁判）

换一个"RAG 质检员"角色 prompt 判 AI 回答：**每个具体数值/条款有没有出处、有没有添油加醋**。

- **正例**：给真块作答 → judge 判忠实。**6/6**
- **反例**：把真值块扣掉，只给一块**无关资料（decoy）**作答 → 好模型该说"知识库暂无此信息"而不是把背到的条款当资料讲。**6/6 无幻觉**

decoy 这招是点睛：把答案藏起来，专门看它会不会"借题发挥"。
正反都过 → 说明生成端不是"检索给什么我照着背"，而是真·有依据才说。

### 4.3 工程细节（能体现你不只会调 prompt）

- 只调**对话 LLM、不碰 qdrant** → 后端不用停，评测可并行跑（上一个评测被 qdrant 单进程锁卡着要停后端）
- 每次请求包 `asyncio.wait_for(90s)` + Semaphore(4) 并发 → 治了之前 judge 段串行卡 6 分钟的毛病
- judge 输出**强制单行 JSON**（`{"faithful":…,"hallucinate":…,"reason":…}`），正则抽 JSON 即可，好解析

## 五、评测的边界（面试主动自曝，最加分）

诚实是评测的人设，三条边界我自己先讲：

1. **judge 是同款模型自评** → 天生偏宽松，只能当**粗筛/回归**，不能当真理。真要权威得上更强模型或人工抽检。
2. **条款虚构 → 正反例都接近天花板** → 判别力没拉开。这次的目的是"证伪 bypass/幻觉"，不是为了刷出梯度。
   要拉开梯度、测服从性上限，应该换成**模型真背得动的常识条款**（如"包邮门槛常见 99"这种预训练高频词）再扰动，看它还跟不跟源——这是下一步。
3. **检索评测 51 条偏"精确条款问法"** → 数字是上界。真实用户口语长尾问法（"我上次那个单子咋退"）要另造问法才测得出来。

## 六、面试速记（60 秒讲法）

> **（开场抛问题）** RAG 答错，到底是检索没找到对的、还是模型不老实？这两段不拆开测，根本说不清。
>
> 1. **地基**：51 条**虚构条款** golden——预训练背不到，才有判别力。
> 2. **切分前置发现**：粗块 7 块时检索全满分=假满分，细切 32 块梯度才出来——**切分决定召回上限**。
> 3. **检索四路 A/B**：向量单跑 Hit@1 只有 51%（条款问题 BM25 反而强）→ 混合 RRF 救回全召回 → 精排把 Hit@1 82→90，生产路径 51/51。
> 4. **生成端扰动**：换值它还答旧值=bypass；清空资料它能答出条款=幻觉。我这 6/6 都过。
> 5. **judge 忠实度**：给真块判忠实 6/6；扣真块只给无关块，不编 6/6。
> 6. **自曝边界**：judge 同款模型自评偏宽松；更强测试是换"模型背得到的常识条款"再扰动。

前面 5 点证明"我知道怎么把效果做出来"，第 6 点证明"我知道评测的边界在哪"——后者是区分普通使用者和大模型工程师的细节。

## 七、跑法速查

| | `rag_eval.py`（检索 A/B） | `rag_quality_eval.py`（生成端） |
|---|---|---|
| 测什么 | Recall@5 / Hit@1 / MRR × 4 策略 | 扰动 V1/V2 + judge 忠实度 |
| 前置 | **先停后端**（qdrant 单进程锁） | 后端不用停 |
| 命令 | `PYTHONPATH=. .venv/Scripts/python scripts/rag_eval.py` | `PYTHONPATH=. .venv/Scripts/python -u scripts/rag_quality_eval.py` |
| 耗时 | ~90s | 几分钟（judge 调用多，受模型响应影响） |
| 什么时候跑 | 改检索/切分前后对比 | 改生成 prompt / 换对话模型后回归 |

> 两个脚本复用同一套 `build_kb` 切块 + 同一批虚构条款，所以检索层的"切分教训"和生成层的"扰动判别"能互相咬合，讲成一个完整故事。
